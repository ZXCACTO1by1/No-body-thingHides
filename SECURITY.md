# Reporting security issues

Do not post exploit details, credentials or personal investigation data in public
issues. Use the official repository's private vulnerability reporting feature
when it is enabled. If it is unavailable, open a minimal issue asking the maintainer
to establish a private reporting channel, without the sensitive details. There is
no separately advertised support email in this release.

Include the application version, Windows version, affected operation and a small
synthetic reproduction. Describe the expected boundary and observed behavior.
Review attachments and filenames before sharing them. Do not attach your database,
cookies, tokens, report archive or an unredacted log.

The local server is intended for the same computer. Do not expose it through port
forwarding or bind a custom client to a public interface. Keep Windows protections
enabled. Verify release checksums before running an archive received elsewhere.
